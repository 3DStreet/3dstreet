# Streets and geospatial components

[Back to the codebase guide](../../CLAUDE.md). Source paths start at the
repository root; bare filenames name modules within this subsystem.

**Curved streets / owned centerlines (#1930 pillar 1):** a managed street OWNS its centerline — `managed-street.points` (street-local control points, `"x y z, …"`, codec in `src/tested/street-centerline.js`) plus `curveType` / `filletRadius` / `closed` on the street; straight = the derived 2-point case. A drawn shape is only an authoring tool (the sidebar copies its vertices in via `shapeToStreetPoints`; `path` is a deprecated copy-in input with a load migration in `src/tested/migrate-street-path.js`). One shared straight→curved mapping (`src/tested/street-path-utils.js`, unit-tested) bends surfaces (as `street-ribbon` geometry: segment, striping, rail, ground) and placements (clones/stencils/pedestrians remapped + tangent yaw); street-align lateral offsets and all straight-space layout code stay untouched. **Street nodes:** the endpoint math lives ONLY in `src/tested/street-nodes-utils.js` (`getStreetNodes`, `endpointLocalZ`, `zStartForAlign`, `getLongitudinalSpan` — generators fill `getLongitudinalSpan(length)` with zero insets, never a hardcoded ±L/2) and the DOM reader `src/aframe-components/street-nodes.js` (`getStreetEndNodesLocal/World`, straight or curved, with `along` into the street body); the `street-graph` scene system derives shared nodes from every street's ends by proximity and records intersections as occupants (`src/tested/street-graph-utils.js`), rebuilt on demand, never serialized. **Read [docs/curved-street-path.md](../curved-street-path.md) before changing centerlines, nodes, the graph, or any ±L/2 span.**

**Generated clone slots and holes (#2011):** `street-generated-clones`, `-stencil`
and `-pedestrians` number their clones in creation order (`data-clone-index`),
stamp each with its straight-space placement (`data-clone-key`, `"x z"` before
any curve bending) and honor a `skip` array of placement holes left by
per-object detach — a layout change that no longer lands on a hole forgets
it; seeded draws must run before the slot counter so a hole never shifts the
clones after it (`src/tested/clone-slots.js`; doc:
[docs/per-object-detach.md](../per-object-detach.md)).

**Geospatial:** `street-geo`, `google-maps-aerial`, `tiled-basemap` (tiled 2D raster basemap on 3d-tiles-renderer; providers/keys via `src/tested/basemap-providers.js` + `config/.env.*`, MapTiler primary — #1962; legacy `mapbox2d` migrates to it at load), `osm-buildings` (2.5D extruded OSM buildings from the basemap provider's vector tiles — MapTiler `tiles/v3` building layer, decoded in `src/tested/vector-tile-buildings.js`; worker pipeline in `src/osm/`, load radius centered on the camera's look-at ground point; the Overpass fetch/cache modules there are no longer used by buildings but are kept for the phase-6 hydrator (#1930); worker code must never import `three`), `osm-streets` (#1930 demo path: streams decoded transportation way records near the camera, draws them as flat class-width ribbons above the ground — one merged vertex-colored mesh per tile from `src/tested/osm-street-ribbon.js`, tint/stacking in `src/tested/osm-street-style.js` — and powers **click-to-upgrade** — an empty-space editor click near a way offers "Generate Street" via `OsmUpgradeChip` (UI copy never says "upgrade", that word means the paid plan; the code keeps the LOD term) and highlights the stretch it would create, minting real `playable` managed streets: the stretch splits at junctions with other ways (`junctionsAlongStretch`/`splitStretchAtJunctions` in `src/tested/osm-street-import.js`), each piece one curved street owning the piece's centerline as `managed-street.points` (`stretchForWindow`; straight when a piece is a single chord; no scaffolding shape), plus a `managed-intersection` per junction where ≥2 generated ends meet (proximity-reused by later generates; curved streets connect to intersections as geometry-only arms) — cross-section from the way's Overpass tags when they arrive in time (`src/tested/osm-way-tags.js`: lanes/oneway/sidewalk/parking/cycleway/name exact where tagged, chip previews what it found), else class+subclass+oneway rules in `src/tested/osm-street-import.js`; roadmap: `docs/osm-street-lod.md`), `geojson`, `geo-flatten`

**Layer opacity (#1754):** `street-geo.opacity` (percent) fans out to every
map layer as a 0–1 fraction. Each layer keeps its stock materials, flips
`transparent` only below 1, keeps depth writes on (a translucent layer still
occludes itself) and, while translucent, moves its meshes to the reference
overlay `renderOrder` so they blend over Gaussian splats instead of hiding
them. Apply opacity through `applyReferenceLayerOpacity` /
`referenceLayerRenderOrder` in `src/tested/transparent-layering.js` (read its
header first), never by hand-setting `transparent`/`opacity` on tile
materials.

**Terrain flattening (#1476):** any number of entities may carry `geo-flatten` (`mode: mesh` = flatten onto the entity's own mesh, for simple primitives; `mode: auto` = invisible footprint proxy plane at local y=0, for complex subtrees). A scene-level `geo-flatten` registry system feeds `google-maps-aerial`, which reconciles shapes in tick with per-entry matrix-change detection and a 150ms throttle (every shape update re-flattens all active tiles on CPU). Managed streets auto-attach `geo-flatten` (mode: auto) in init — same pattern as `street-align`/`street-ground` — so streets flatten terrain under their footprint by default. `street-geo.enableFlattening` (default true) is the master gate; the legacy single-shape `street-geo.flatteningShape` reference is migrated to a `geo-flatten` component at load (`migrateLegacyFlatteningShape` in `src/json-utils_1.1.js`). Never raycast a street's real meshes for flattening — slow, and terrain would snap to the tops of vehicles/trees.
